# 07 · 重构路线图与验收

> 原则：**每一步结束游戏都必须能跑、必须有可执行的验证**。不做"大爆炸式重写"。
> 整个路线共 5 个阶段，每阶段独立可交付。预计 `domain` 层可从"零测试"到"覆盖核心规则"。

```python
# tests/golden/test_baseline.py
def test_level_signature(snapshot, level_index):
    game = make_game(level_index, seed=2718)
    game.step_n_frames(600)                     # 不动渲染，只跑 update
    sig = {
        "plants": sorted((p.ptype, p.col, p.row, round(p.hp)) for p in game.plants),
        "zombies": sorted((z.ztype, z.row, round(z.x)) for z in game.zombies),
        "sun": game.sun,
        "wave": game.current_wave_index,
        "total_zombies": game.total_zombies,

    assert sig == snapshot[f"level_{level_index}"]
```

```python
FORBIDDEN = {"domain": {"pygame", "infra", "app", "usecases"}}
def test_domain_has_no_outer_deps():

        tree = ast.parse(f.read_text(encoding="utf-8"))
```

## 2. Phase 2：消解"必须耦合"的错位（4–6 天，收益最大）

### 2.1 `FieldLayout`（`06 §6`）

1. 新建 `domain/spec/field_layout.py`，把 `POOL_ROW_CENTERS` / `POOL_LANE_GROUNDS` / `POOL_ROW_RANGES` 与 `_cell_at` 的硬编码区间**合成一张表**。
2. 先核对三张表是否自洽。**实测结论（`01 §7`）：三张表彼此自洽** —— `ROW_RANGES` 中点与 `ROW_CENTERS` 差 ≤13px，`LANE_GROUNDS` = 中心 + 22~42px。真正的错误不在表，而在 5 个调用点漏传 `is_pool` / `cell_h`，导致泳池关并存三套地面高度。
   → **基准应以 `POOL_ROW_CENTERS` / `POOL_LANE_GROUNDS` / `POOL_ROW_RANGES` 为准**（它们是为贴图专门对齐过的），把 `_cell_at` 的阈值改为从同一表推导：
```python
row_bounds = [(c - h//2 - 8, c + h//2 + 8) for c,h in zip(row_centers, row_heights)]
```
3. 全部调用点改 `world.layout.ground_y(row)`。
4. **验证**：泳池关截图与基线对比，僵尸应精确站在水面行上（现状：渲染地面与逻辑地面偏差 8–49px，`01 §7` 有三套地面高度实测表）。这一步会**改变画面**，属于修 bug。

### 7.3 架构守则（写进 `AGENTS.md` / `CONTRIBUTING.md`）

1. **`domain/` 不允许 `import pygame`**。需要图形的地方用 `RectTuple` / 快照 DTO。
2. **不许再出现"改代码的脚本"**。改代码就用编辑器 + git；`tools/` 只放资产与运维脚本。
3. **新增植物/僵尸/弹种/关卡只改 `domain/spec/`**。若需要改 `rules/`，说明当时的数据表达力不够，先扩 spec 再改。
4. **规则不产生表现副作用**。规则只 `emit(event)`；音效/粒子/飘字由 `infra/fx.py` 订阅。
5. **禁止 `setattr(obj, ...)` 挂未声明字段**。字段必须写在 dataclass 里。
6. **命中区域由布局纯函数产出**，渲染与输入都不持有几何状态。
7. **跨模块字符串用枚举**，并在启动期做一致性自检。
8. **PR 必须附带快照测试**（新增玩法加新快照，改数值更新快照并说明理由）。

## 8. 风险与对策

| 风险 | 症状 | 对策 |
|---|---|---|
| **"等价重构"变成"顺手改行为"** | 快照测试变动但说不清为什么 | 快照 diff 必须逐条解释；确属修 bug 的单独提交并加回归测试 |
| **泳池几何合并时选错基准** | 僵尸位置整体偏移 | 先用脚本枚举 6 行 × 9 列的 `center/ground/bounds`，人工对照截图确认基准；合并后再次截图 |
| **Phase 4 拆 `Game` 时引用漏改** | 运行期 `AttributeError` | 过渡期用 `__getattr__` 转发 + `mypy` 检查；每拆一个用例跑一次快照 |
| **配置数据化时数值抄错** | 快照漂移 | 数值搬迁用脚本从旧 `elif` 块抽取（一次性），并用快照 + 单植物伤害测试双重校验 |
| **测试改造期间存档污染** | 开发者存档被测试写坏 | 全部测试用 `tmp_path` 注入 `SavePath`；`SavePort` 构造参数化 |
| **多人/多分支并行** | 重构与大功能冲突 | 阶段间不合并功能分支；Phase 1 完成后冻结 `Game` 的改动，功能只改 `spec` |
