# 03 · 耦合分级诊断

> 分类标准（依耦合度由轻到重）：
> **非直接耦合** → **数据耦合**（只传简单数据参数）→ **标记耦合**（传整个记录/结构，只用其中一部分）→ **外部耦合**（共同依赖外部格式/设备/约定）→ **公共耦合**（多个模块共享同一全局可变数据）→ **内容耦合**（一个模块直接读写另一模块内部实现）
>
> 本文按此标准逐条定位本项目中的耦合，并给出**降级目标**与**降级手段**。方案落地细节见 `05-目标分层与模块划分.md`。

---

## 0. 结论摘要

| 等级 | 本项目中的典型实例 | 数量级 | 处置 |
|---|---|---|---|
| 非直接耦合 | `pvz_graphics` ← 被 `Game` 单向调用（部分） | 少 | 保留 |
| 数据耦合 | `cell_center(col,row,cell_h,is_pool)`、`clamp/lerp` | 少 | 保留并扩大 |
| 标记耦合 | `Projectile.update(dt, game)` 传整个 `Game`；`draw_plant(..., plant=plant)` 传整个 `Plant`；`Mower.update(dt, game)` | 5 类 | **必须降级** |
| 外部耦合 | 存档 JSON 键名、`music_*.mp3` 命名、`assets/plants/<key>` 目录约定、`bullet_type` 字符串、`theme` 字符串 | 6 组 | 收敛为单一常量源 |
| 公共耦合 | `self.sun`、`self.artifacts`、`self.is_pool`、`self.pool_rows`、`self.cell_h`、**5 个 draw 写入的 rect 字典**、模块级 5 个 `_*_CACHE` | 12+ 处 | **最需要优先处理** |
| 内容耦合 | 绘制路径写 `seed_rects` 等命中框；`_update_plants` 直接 `z.hp -= 22`；`Projectile.update` 遍历并重定向 `game.zombies`；`pvz_graphics` 读 `plant.squash_state`/`zombie.hypnotized`；`setattr` 动态挂字段 | 8 类 | **最需要优先处理** |

**一句话诊断**：本项目的主要问题不是"耦合太多"，而是**耦合错位**——把本该是数据耦合的地方做成了标记/内容耦合，把本该有单一权威的地方做成了公共耦合。真正"必须保留"的耦合只有三类（见 §1），其余几乎都可降级。

## 1. 哪些耦合是"必须的"（无法也不该消除）

判定标准：**两个模块必须同时知道某个事实，否则系统行为无法成立**。这类耦合应当被**显式化并收窄**，而不是被消灭。

### N1. 规则 × 实体状态 —— 必须耦合

`_update_plants` 必须读 `plant.age/action_timer/alive`、必须写 `self.projectiles`，`_update_zombies` 必须读 `plant.hp` 并写 `zombie.eating`。

这是"模拟器驱动实体"的本质耦合。**降级目标：内容耦合 → 数据耦合**，手段是引入**端口（Port）接口**：规则只依赖
```python
def try_damage(zombie_id, amount, *, freeze=False) -> None
def spawn_projectile(spec: ProjectileSpec) -> None
def zombies_in_row(row) -> Iterable[ZombieView]
```
而不是 `self.` 加一长串属性名。规则不再知道"僵尸列表存在哪个字段"。

### N2. 规则 × 网格几何 —— 必须耦合

任何"碰撞/落点/寻路"都必须知道列宽、行地面高度、水陆划分。`lane_ground` 被 15 处调用，不是坏事。

**降级目标：内容耦合 → 数据耦合**，手段是把三张泳池常量表合并为**一个 `FieldLayout` 值对象**，以参数传入：
```python
layout.center(col,row) -> (x,y)
layout.ground_y(row) -> float
layout.cell_rect(col,row) -> Rect
layout.is_water(row) -> bool
```
规则拿到的是"一个几何值对象"，而不是"必须去问 `Game`"。

### N3. 规则 × 配置数值 —— 必须耦合

`PLANTS[name]["hp"]`、`ZOMBIES[ztype]["speed"]` 都是合法的数据耦合（传入 key 取数）。真正的问题在于**表达力不足**：34 种植物只有 4 个数值字段，导致行为只能写进 `elif`。

**降级目标**：保持数据耦合，**扩充配置表**成为"行为配方"（见 `04-耦合降级手册.md` §3），使新增植物只需改数据、不改分支链。

### N4. 领域事件 × 表现 —— 必须耦合（但只允许单向）

"僵尸死了要冒粒子+播音效"是产品需求。**但方向必须是 领域 → 表现**，不能是 规则代码里直接 `self.audio.play("chomp")`。

**降级目标：内容耦合 → 通过事件队列的非直接耦合**。规则 `emit(GameEvent(kind=ZOMBIE_DIED, x=..., y=...))`，表现层订阅并决定粒子/音效/飘字。

### N5. 输入 × 命中区域 —— 必须耦合，但必须是**数据**方向

点击处理必须知道"卡牌在哪个矩形"。**但这应当是 布局 → 输入 的只读传参**，现状是反的：`draw` 写 `self.seed_rects`，`click` 读它（§3 的 C2）。

## 2. 标记耦合（marker coupling）—— 6 处，必须降级

定义：把整个结构传给对方，而对方只用到其中一小部分字段，导致"双方都依赖这个结构的全部形状"。

### M1. `Projectile.update(self, dt, game: object)` —— 最典型的标记耦合

```python
# 1450–1526
def update(self, dt, game: object = None) -> None:
    if self.is_homing:
        if game and hasattr(game, "zombies"):
            alive_z = [z for z in game.zombies if not z.dead and not getattr(z,"hypnotized",False) ...]
```
**问题**：弹丸为了"重定向"拿到了整个 `Game`，同时：
- 参数类型是 `object` → 零类型信息
- 用 `hasattr(game,"zombies")` 试探 → 说明它自己也不确定会收到什么
- 读了 `game.zombies` 的 `dead/hypnotized/x/ztype/flying` 五个字段 → 弹丸因此依赖 `Zombie` 的内部形状
- 参数名叫 `game` → 弹丸依赖"存在一个叫 game 的东西"

**降级**：改数据耦合。
```python
# 领域内定义
class TargetProvider(Protocol):
    def best_target(self, *, exclude_hypnotized: bool = True) -> "Target | None": ...
    def target_alive(self, ref) -> bool: ...
# Projectile 只接受 target_provider
Projectile.update(dt, target_provider)
```
`Projectile` 从此不知道 `Game`、不知道 `Zombies` 列表、不知道任何集合字段。

### M2. `Mower.update(self, dt, game: "Game")`

```python
# 1537–1551
game.sun += 200
game.float_text(...)
game.burst(...)
game.audio.play("collect")
game.kill_zombie(zombie, mower=True)
```
**问题**：推车读了 `game.artifacts / game.sun / game.zombies`，写了 `game.sun`，还调了 4 个 `Game` 方法。推车现在是 `Game` 的**内部组件**，无法单测，也无法复用到别的模式。

**降级**：推车只应该产出两个事实：「我碾过了这些僵尸」+「我该被标记为已用」。金币奖励是 `golden_mower` 神器规则，属于奖励层。
```python
# 推车
def update(self, dt, lanes: LaneQuery) -> list[ZombieRef]: ...   # 返回被碾的引用
# 调停者在 Game(应用层) 里：
for ref in mower.update(dt, lanes): simulation.kill(ref, cause=MOWER)
if rewards.has("golden_mower"): rewards.grant_sun(200, at=mower.pos)
```

### M3. `draw_plant(..., plant=plant)` —— 表现层吃整个模型

```python
# 811–820 签名带 plant: "Plant" | None = None
# pvz_graphics.py:941  if plant and plant.squash_state == "jump":
# pvz_graphics.py:960  swallow = plant.swallow_timer if plant else 0.0
```
**问题**：图形层为了画"跳跃中/咀嚼中"读到 `Plant` 的两个内部字段。于是**改一个玩法字段名就破坏渲染**，且图形层递归依赖了 `Plant` 定义（虽然只靠 duck-typing）。
另外 `render_zombie_sprite` 读 `eating/enraged/hypnotized/is_submerged/flying/digging/emerged/slow_timer` 等十余个字段。

**降级**：定义**渲染快照**（只读值对象）：
```python
@dataclass(frozen=True)
class PlantRenderState:
    ptype: str; center: tuple[float,float]; scale: float
    hp_ratio: float; age: float; anim: str = "idle"   # anim: idle|attack|jump|chew|cracked
```
规则层负责把 `squash_state=="jump"` 翻译成 `anim="jump"`。图形层从此**只认快照，不认模型**——两者通过一个 5 字段的 DTO 达到数据耦合。

### M4. `_damage_zombie(zombie, damage, freeze)` 之后各处**继续操作同一 zombie**

```python
# 2998–3004  _damage_zombie 内部已做 hp<=0 → kill_zombie
# 2707–2710  spikeweed 分支却绕过它：z.hp -= 22.0; if z.hp<=0: self.kill_zombie(z)
# 2733–2736  iceshroom 同样绕过
# 3344–3346  _explode_radius 同样绕过
```
**问题**：伤害规则有 4 套实现（`_damage_zombie`、spikeweed、iceshroom、`_explode_radius`/`_burn_lane`），只有第一套处理了读报僵尸的护盾、冰冻减速、受击闪白、粒子。另外三处直接改 `hp`，导致**报纸僵尸被地刺/毁灭菇/核弹打死时报纸不碎**（行为不一致，且无法从代码阅读中发现）。

**降级**：把"造成伤害"收敛为**单一权威** `apply_damage(zombie, amount, source)`，所有入口（射线、范围、行、吞噬以外的致死）都调它。这是"消除公共/内容耦合"最划算的一处。

### M5. `_handle_click` 里读 `self.selected_plant / self.shovel_selected / self.mode / self.overlay / self.sun / self.cooldowns / self.artifacts / self.selected_seeds / self.slot_capacity`

一个方法依赖 9 个 `Game` 字段并写 5 个。它本质上是"**8 个不同 UI 上下文的点击处理器**被塞进一个方法"，通过 `mode/overlay` 分支选择。

**降级**：按上下文拆成 8 个互不认识的处理器，由 `mode/overlay` 做路由表：
```python
handlers = {"menu": self._click_menu, "seed_select": self._click_seed_select,
            "warp": self._click_warp, "paused": ..., "won": ..., "lost": ...,
            "playing_hud": ..., "playing_field": ...}
```
每个处理器只拿到它需要的那几个依赖（构造参数注入）。

### M6. `setup_preview(level_index)` —— 116 行硬编码场景

它把演示场景（两套植物/僵尸/子弹/阳光坐标清单）写进 `Game`，只服务于 `--preview/--smoke-test`。它依赖 `Plant/Zombie/Projectile/SunToken/PLANTS/ZOMBIES/cell_h/lane_ground` 共 8 个东西。

**降级**：抽出为 `infra/demo_scene.py` 中的数据 + 一个 `.build(world) -> None`。`Game` 只保留 `setup_preview` 作为一行委托（或直接由 `main` 调用）。

## 3. 公共耦合（common coupling）—— 最严重的一类

定义：多个模块读写同一个全局可变数据，改一处会影响所有读写者，且影响范围不可见。

### C1. `self.sun` —— 裸 int，6 个职责直接读写

| 位置 | 读写 |
|---|---|
| 1542 `Mower.update` | `+= 200` |
| 1662 `start_level` | `=` 初始值 |
| 2194 `_handle_click` | `+= cost`（金铲） |
| 2248 `_handle_click` | `-= cost` |
| 2302 `collect_sun` | `+= value` |
| 3231 `_spawn_endless_wave` | `+= 150` |
| 3925 `_draw_hud` | 读 |

**影响**：想加"阳光上限"或"阳光特效"或"统计产出"，必须改 7 处。游戏中任何一处漏改都静默生效。

**降级**：`SunEconomy` 值对象（`gain(amount, reason)` / `try_spend(amount) -> bool` / `balance`），所有写入走同一个方法，`reason` 让 HUD 和特效可以订阅。

### C2. **绘制写命中框 → 输入读命中框（最恶劣的一处）**

```python
# 写（绘制路径）
_draw_menu(3534,3548,3575,3596)     -> self.level_buttons
_draw_seed_select(3649,3705,3711)   -> self.slot_rects / self.catalog_rects
_draw_hud(3928,3935)                -> self.seed_rects
_draw_overlays(4093,4100)           -> self.warp_buttons

# 读（输入路径）
_handle_click(2066,2087,2093,2173)  -> 同名字段
```

**危害（已可在代码中证实）**：
1. **时序依赖**：如果第一帧 `draw` 未执行（如 `headless` 且从不 `draw`，或 `mode` 刚切换那一帧），`seed_rects` 是空字典 → 所有卡牌点击静默失效。`test_pool_planting_and_cards.py` 这类测试必须先 `game.draw()` 才能 `_handle_click`。
2. **几何反了**：`_draw_hud` 用 `pygame.mouse.get_pos()`（3939）做 hover，`handle_events` 用 `get_logical_mouse_pos()`（1931）做点击 → 全屏下 hover 与点击不一致。
3. **布局不可测**：布局无法在没有 `Surface` 的情况下计算，无法写纯逻辑测试。
4. **表现层被赋予领域职责**：`_draw_seed_select` 调 `available_plants()`（3697），该方法会 `self.artifacts.add(...)`（1851）——**每帧绘制都会给玩家发神器**。

**降级**：
```
Layout (纯函数)  ──产出──>  LayoutSpec { hit_regions: dict[str, Rect], draw_cmds: [...] }
                              │
        ┌─────────────────────┴──────────────────┐
     Input 读 hit_regions                 Renderer 消费 draw_cmds
```
`Layout` 只依赖"当前状态快照"（尺寸、模式、卡槽数量），不依赖 `pygame` Surface，可离线跑单测。`Input` 与 `Renderer` 互不认识，都只认识 `LayoutSpec`。这是**公共耦合 → 数据耦合**的标准解法。

### C3. `self.is_pool / self.pool_rows / self.cell_h / self.rows / self.grid_bottom` —— 5 个字段表达同一件事

这 5 个字段在 `start_level`(1652–1656) 同时赋值，之后被 **20+ 处** 读取。它们是"场地形状"的 5 个碎片，任何一处不同步就产生几何错乱。

**已证实的事故**：`lane_ground` 有 38 处调用，**36 处没传 `is_pool`**（只有 `Zombie.y` / `Zombie.rect` 传了）。于是 `draw_zombie`（渲染）、`kill_zombie`、`_explode_radius`、`_burn_lane`、`Mower.update` 全部在泳池关走了陆地公式，僵尸渲染地面与逻辑地面最多相差 **49px**（`01 §7` 有完整量化表）。这不是粗心——**是因为 `is_pool` 是一个"可选参数"，调用方有权不传且编译器不报警**。

**降级**：合并为**不可变** `FieldLayout`（见 N2），单一赋值点，其余全部读 `world.layout`。

### C4. `self.artifacts` —— 一个 set，被 5 个不同层读写

| 位置 | 行为 |
|---|---|
| 1572/1658 `__init__/start_level` | 从存档 union（且注释表明曾被重复 union，见 `tools/fix_art.py`） |
| 1851/1856 `available_plants` | **在"查询"里 add** |
| 1573/1659 | 决定 `slot_capacity` |
| 1661 | 决定 `auto_sun_unlocked` |
| 2190/1540/2249/1662 | 4 个神器效果各自检查 |

**降级**：`UnlockState` 值对象 + `UnlockPolicy`（纯函数：`completed_levels → rewards`）。神器效果改为注册表 `{artifact_id: effect_fn}`，而不是散落的 `if "xxx" in artifacts`。

### C5. 模块级 5 个绘制缓存 `_TEXT_CACHE / _LEAF_CACHE / _SUN_GLOW_CACHE / _GLOW_CACHE / _PARTICLE_CACHE`

它们是无界全局可变 dict，**跨实例共享**（多个 `Game` 实例/多个测试共用一个进程时会互相污染），且 `text()` 用 `id(font)` 作 key（字体的 `id` 复用时缓存可能错命中）。

更严重的是 **`_PARTICLE_CACHE` 的 Surface 被就地 `set_alpha` 后 blit**（3863）：
```python
sprite = _PARTICLE_CACHE.get(key) or 创建
sprite.set_alpha(alpha)     # ← 修改的是缓存里的那个 Surface
self.screen.blit(sprite, ...)
```
同一 key 的粒子在同一帧内如果 alpha 不同，后画的会覆盖前者的 alpha → 视觉抖动。同理 `FloatingText.image`(3870) 是复用的 Surface，也被 `set_alpha` 就地改。

**降级**：缓存进 `Renderer` 实例（`self._cache`），生命周期跟随渲染器；`set_alpha` 改为 `sprite.copy().set_alpha()` 或改用 `surface.fill(color, None, BLEND_RGBA_MULT)` 的预乘方案。

### C6. `Record_win` 与 `self.save_data` 双写

`record_win()` 是模块级函数：内部 `load_save()`（读盘）→ 改 → 写盘。而 `Game.save_data` 是内存副本，只在 `__init__/start_level` 刷新。

**后果**：通关后 `record_win` 已写盘，但 `self.save_data` 仍旧是旧值；`available_plants()` 又自己 `load_save()` 一次（1834）。同一次通关，存档被读 2 次写 1 次，内存副本与磁盘不一致。

**降级**：`SaveRepository`（唯一读写点，带内存缓存 + `flush()`），`Game` 不持有 `save_data`，需要时读 `self.progress`（领域值对象）。

## 4. 内容耦合（content coupling）—— 直接触碰对方内部实现

### K1. 规则代码直改实体字段而非走实体方法

```python
2707  z.hp -= 22.0
2733  z.hp -= 35.0
2828  zombie.hp = 0
2905  plant.hp -= dmg
2998  zombie.hp -= damage
3344  zombie.hp -= damage
3355  zombie.hp = 0
2835  p_item.alive = False      # 小丑自爆直接杀植物
2191  top_plant.alive = False   # 铲子直接杀植物
2226  carrier.alive = False     # 种猫尾草直接消耗睡莲
2732  z.slow_timer = 12.0
3102  z.slow_timer = 6.0
2917  setattr(zombie, "hypnotized", True)
2918  zombie.speed = -abs(zombie.speed)
```
`hp` 被 7 处直接写，其中 4 处绕过了 `_damage_zombie` 的全部副作用。

**降级**：实体提供 `take_damage(amount, source) -> DamageResult(died: bool)`；`alive` 改为只读属性 + `kill(reason)`；状态变更走 `apply_status(Slow|Butter|Hypno, duration)`。

### K2. `setattr` 动态挂字段（类定义中不存在的属性）

| 位置 | 挂上什么 | 谁在别处读 |
|---|---|---|
| 2434–2435 | `proj.vx` / `proj.vy` | 3012 `hasattr(projectile,"vx")` |
| 3024 | `projectile.hit_set` | 3023 |
| 2917 | `zombie.hypnotized` | 12 处 `getattr(z,"hypnotized",False)` |
| `_update_plants` 2567 | `plant.shots_since_butter` | 同方法 |
| `Mower.update` 1541 | `mower.rewarded_gold` | 同方法 |
| 2483 | `proj.suit` | 图形层 |

**危害**：字段存在性在运行期才确定 → 静态检查全失效、IDE 无法补全、拼写错误静默变成"字段不存在"。`zombie.hypnotized` 明明在类里定义了（1416），却仍用 `setattr` + `getattr` 双重动态访问，说明**连作者都不确定字段有没有**。

**降级**：全部提升为 dataclass 字段。`vx/vy` 提升后，`_update_projectiles` 开头的 `hasattr` 特例分支可以直接删除（变成弹丸自身的一种运动模式）。

### K3. 实体反向依赖 `Game`（双向依赖）

```
Game ──持有──> Plant / Zombie / Projectile / Mower
  ▲                        │
  └────────调用/读写────────┘   Projectile.update(game)、Mower.update(game)
```
双向依赖意味着**两个模块必须一起改、一起测、一起版本化**——它们实际上是一个模块，只是被写成了两个。

**降级**：见 M1/M2，把反向依赖替换为**端口接口**（`TargetProvider` / `LaneQuery`），依赖方向变为单向：`Game → 实体`，实体只依赖 `Protocol`。

### K4. 图形层读模型内部字段

`pvz_graphics.render_plant_sprite(..., plant=plant)` → `plant.squash_state`、`plant.swallow_timer`。
`render_zombie_sprite(zombie)` → `ztype/eating/enraged/hypnotized/is_submerged/flying/digging/emerged/slow_timer/butter_timer/death_timer`（十余个）。

**降级**：见 M3，传 `PlantRenderState` / `ZombieRenderState` 快照。

### K5. `text()` 用 `setattr(rect, anchor, ...)` 动态设置锚点

```python
672  setattr(rect, anchor, (round(pos[0]), round(pos[1])))
```
`anchor` 是 `"topleft"/"center"/"midtop"/"topright"` 等字符串，靠 `Rect` 的属性名反射。调用方传错字符串 → `AttributeError` 在运行期才炸（且 20+ 调用点没有一个集中校验）。

**降级**：`Anchor` 枚举（`Topleft | Center | Midtop | Topright`），`place(rect, anchor, pos)` 用 match 分支。类型检查器可校验。

### K6. `_update_waves` 依赖 `LEVELS` 里 dict 的 `get` 方法被"保护"

```python
1688  getattr(level, "get", lambda k, d=None: d)("endless", False)
3204  getattr(LEVELS[self.level_index], "get", lambda k: False)("endless")
3369  同上
```
对一个已知是 `dict` 的对象做 `getattr(level,"get",...)` —— 说明作者一度把它当对象、一度当字典。这是"配置表无类型"的症状。

**降级**：`LevelSpec` dataclass，`level.is_endless` 是布尔字段。

## 5. 外部耦合（external coupling）

定义：两个模块都依赖同一个**外部格式/设备/第三方便利**，而非依赖彼此的接口。

| # | 外部约定 | 依赖方 | 风险 |
|---|---|---|---|
| E1 | 存档 JSON 键 `completed/artifacts/endless_best/highest_level` | `load_save`、`record_win`、`available_plants`、`start_level`、`_draw_menu` | `highest_level` 从未被写入，只被读(1661) → 该解锁条件永远不成立 |
| E2 | `music_{track}.mp3` 文件名 | `AudioBank.play_music` + 4 处调用方传 `"menu"/"day"/"night"/"endless"/"seeds"` | 字幕错拼静默静音 |
| E3 | `assets/plants/<key>/idle_N.png`、`assets/cards/card_<key>.png` | `pvz_graphics.init_graphics` + `PLANTS` 键名 | 新植物必须三处命名一致 |
| E4 | `LEVELS[i]["theme"]` 字符串 == `assets/maps/<theme>.*` 文件名 | `_background`、`draw_zombie` 主题、`_draw_menu` 配色分支 | 三种写法并存（§01 §7） |
| E5 | `bullet_type` 字符串 == 图形层分支 | `get_bullet_surface`、`_draw_entities` | 新弹种无贴图 |
| E6 | `pygame.mouse.get_pos()` 是**窗口坐标**，`get_logical_mouse_pos()` 是**画布坐标** | 5 处直接用前者、其余用后者 | 全屏下混用失效 |
| E7 | 冻结 Windows 定时器精度 `ctypes.windll.winmm.timeBeginPeriod(1)`(1–6)、`C:\Windows\Fonts\msyh.ttc`(480)、`pygame.DOUBLEBUF|HWSURFACE`(4373) | 平台相关，写死在业务模块 | 非 Windows 直接崩或降级 |

**降级**：
- E1/E3/E4/E5 → 建立**单一命名常量/注册表**（`PlantId`、`LevelId`、`BulletKind` 枚举 + `AssetManifest` 映射），并在启动时做一次**一致性自检**（`assert set(PLANTS) == set(manifest.plants)`），把外部耦合的失败从"运行期静默"提前到"启动期报错"。
- E6 → 全项目只留 `Viewport.to_canvas(raw_pos)` 一个入口，并禁止 `pygame.mouse.get_pos()` 出现在 `Game` 与 renderer 之外。
- E7 → 抽 `platform/windows_tweaks.py`、`platform/font_loader.py`，用 `try/except` + `sys.platform` 守卫，主模块不再 import `ctypes`。

## 7. 应当保留（不降级）清单

避免"为了解耦而解耦"：

- `_update_plants` 读 `plant.age` / 写 `world.projectiles`：模拟器与实体的本质耦合，只做**端口化**（N1），不做"事件驱动实体"。
- `lane_ground` / `cell_center` 被 15 处调用：几何是公共语言，**保留函数形态**，只把实现收敛到 `FieldLayout`。
- `PLANTS[name]["cost"]`：数据耦合，正确。只需**扩充字段**而非拆分。
- `Game.update` 里固定的 8 步顺序：这是**帧编排**，属于应用层的合理职责，不必拆成"流水线框架"。
- 单一 `Game` 类持有本局所有可变状态：**保留**，但把状态**归集为值对象**（`World` / `LevelSession`）而不是 138 个平铺字段。
