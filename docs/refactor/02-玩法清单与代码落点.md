## G1 网格与场地

**规则**
1. 陆地：5 行 × 9 列，`GRID_X=70 GRID_Y=124 CELL_W=111 CELL_H=116`。
2. 泳池：6 行 × 9 列，`cell_h=96`，行 2/3 为水。
3. 泳池用的是**完全不同的列几何**：`x = 140 + col*80`（列宽 80），行中心/行地面/行范围三张独立常量表。
4. 只有水面行允许种睡莲；只有睡莲上能种其他植物（猫尾草除外，它种在睡莲上但会消耗睡莲）。
5. `spikeweed`/`potatomine` 不能种在水上。
6. 鼠标坐标在点击时需要反解成 `(col,row)`。

**落点（共 9 处，规则散落最严重的地方）**

| 位置 | 内容 |
|---|---|
| 33–40 | 陆地网格常量 |
| 455–466 `cell_center` | 陆地：`GRID_X + (col+0.5)*CELL_W`；泳池：`140 + (col+0.5)*80`，`POOL_ROW_CENTERS` 常量内联 |
| 469–474 `lane_ground` | 陆地：`GRID_Y+(row+1)*cell_h-(13 or 8)`；泳池：`POOL_LANE_GROUNDS` 内联 |
| 1911–1918 `get_cell_rect` | **第三套**泳池几何：`POOL_ROW_RANGES` 内联 + `gx = 140 + col*80` |
| 2255–2281 `_cell_at` | **第四套**泳池几何：写死 `140/860/90/210/335/452/560/660/755` |
| 1655 | `pool_rows = [2,3]` 写死 |
| 1789–1806 `_build_waves` | 泳池车道 `[2,3]` 写死，水路/陆路僵尸分流规则写死 |
| 3260–3266 `_spawn_wave_member` | 又一遍水路/陆路分流规则 |
| 2183/3802/3808/3886 | 四处 `is_pool and row in pool_rows` 的重复判断 |

> 三张泳池行常量表（`POOL_ROW_CENTERS` / `POOL_LANE_GROUNDS` / `POOL_ROW_RANGES`）互不引用、数值需手工保持一致（实测三者自洽，见 `01 §7`），列几何统一为 `x = 140 + col*80`。真正的问题不是表不一致，而是 **38 处 `lane_ground` 调用里有 36 处没传 `is_pool`**（含渲染路径 `draw_zombie`、死亡结算、爆炸判定），导致泳池关走了陆地公式。

## G2 阳光经济

1. 自然阳光：白天 6.5–9.5s / 夜晚 14–18s 掉落 1 个（`_spawn_natural_sun`，夜间固定 25 点、白天默认 25 点）。
2. 生产植物：`sunflower` 首次 4.1s 之后 7.0s，25 点；`twinsunflower` 4.0/6.8s，两个 25 点；`sunshroom` 6.5/8.5s，35 岁前 15 点、之后 25 点。
3. 手动收集：点击/鼠标悬停命中 `SunToken.contains()`（半径 38）。
4. 自动收集：`auto_sun_unlocked` 且 `auto_sun_enabled` 时 `_update_visuals` 每帧扫一遍，`age>=0.25` 即收（注意：这个效果被放进了"视觉更新"方法里）。
5. 阳光进入 `self.sun`，被种植扣费、黄金铲子返还、镀金推车奖励、无尽波次奖励共同读写。

**耦合点**：`self.sun` 是一个裸 int，被 6 个模块级职责直接 `+= / -=`（2194、2248、2302、3231、1542）。

## G3 种植与卡槽

1. 卡槽容量 9（大师腰带 10），来自 `slot_capacity`。
2. 可解锁植物由"已通关关卡奖励"∪"跳关补发"∪"第 16 关全解锁"决定，并强制补齐 `lilypad`（`available_plants`）。
3. 智能推荐卡组（`_recommend_seeds`，41 行优先级链，硬编码 20 个植物名）。
4. 选卡界面：34 种目录网格、点击加入/移出、清空、推荐、确认。
5. 战斗中选卡：点击 HUD 卡牌选中/取消，数字键 1–9 快捷选取。
6. 种植判定：陆地占位检查、水面睡莲承载检查、猫尾草消耗睡莲、升级替换（`gatlingpea` ← `repeater`，`twinsunflower` ← `sunflower`）。
7. 冷却：`cooldowns[name]` 每帧递减，种植后设为 `cooldown * (0.7 if rapid_seeds)`。
8. 铲子：移除植物，黄金铲子全额返还。
9. 幽灵预览：鼠标所在格高亮 + 半透明植物 + 可否种植的红叉（`_draw_entities` 3868–3910）。

**耦合点：种植规则被实现了两遍，且已经不一致。**

| 规则 | 战斗点击 `_handle_click` (2211–2240) | 幽灵预览 `_draw_entities` (3886–3905) |
|---|---|---|
| 水上禁种 spikeweed/potatomine | ✅ | ✅（白名单 `not in (...)` 排除） |
| 猫尾草需睡莲且消耗睡莲 | ✅ | ✅ 判定一致（预览不真正消耗） |
| 陆地已有植物则拒绝 | ✅ | ✅ |
| 睡莲只能种在水中 | ✅ | ✅ |
| **升级替换 gatlingpea←repeater / twinsunflower←sunflower** | ❌ **未实现** | ✅ **只有预览有** |
| 铲子/卡牌/HUD 命中 | ✅ | – |

也就是说：**预览高亮显示"可以升级"，点下去却被拒绝并提示"这里已有植物"。**这是唯一一致性问题，但足以让玩家困惑（种在豌豆射手上的机枪射手永远无法落地）。

> 另外，预览的格高亮矩形来自 `get_cell_rect`(第三套泳池几何)，而落点判定来自 `_cell_at`(第四套泳池几何)，两者在泳池关的边界可能不一致——同一个格子可能出现"高亮在此格、点击判到隔壁格"。

## G7 波次与关卡节奏

1. 每关 3–6 波，波内成员间隔 1.2–2.8s（第 10 关后 1.6–2.8）。
2. 权重曲线 `0.75 + i*0.12`，最后一波 ×1.35。
3. 波间推进：HP 比例低于阈值 或 定时到期 且无待刷成员 → 下一波。
4. 最后一波强制覆盖行（`member_index < rows` 时逐行铺满）。
5. 首波 15s 后开始（`FIRST_WAVE_DELAY`）。
6. 无尽模式：场上清空后生成新一轮，`count = min(35, 12+wave*2)`，每次 +150 阳光，写存档。
7. 波次 HUD：进度条 + 每波刻度 + `spawned/total` 计数。

**耦合点**：`_build_waves` 同时依赖 `self.rows`、`self.is_pool`、`self.level_index`、`LEVELS`、`ZOMBIES`；`_wave_hp_ratio` 需要 `ZOMBIES` 的 hp 与 `pending_wave_spawns`；`_spawn_wave_member` 再依赖 `self.cell_h`。**一个纯算法函数被 `Game` 的 5 个属性绑死，因此无法单测。**

## G9 胜负与结算

1. 普通僵尸 `x < MOWER_X-6` → `overlay="lost"` + `lose_reason` + 停音乐 + 音效（在 `_update_zombies` 里）。
2. 最后一波清空 → `overlay="won"` + `record_win` + 烟花（在 `_check_progress` 里）。
3. 结算弹窗（`_draw_overlays` 4152 起）显示赢/输标题、奖励植物、神器说明、下一关按钮。
4. 奖励发放逻辑在 `record_win`（模块级函数）与 `LEVEL_REWARDS` 之间，实际展示在 `_draw_overlays`。

**耦合点**：`record_win` 是模块级函数，直接写文件，与 `Game` 的 `save_data` 无关联；`start_level` 又读一遍文件。同一份存档在一次"过关→下一关"的流程里被读 3 次、写 1 次。

## G10 进度与解锁

1. 初始植物：`DEFAULT_INITIAL_PLANTS = ["sunflower","peashooter"]`。
2. 通关奖励：`LEVEL_REWARDS[i]["plants"]`，共 15 条，合计 32 种植物。
3. 跳关补发：`for prev_idx in range(level_index)` 把之前所有关卡奖励连**神器**一并补上（含 `self.artifacts.add`）。
4. 第 16 关（index 15）直接全植物 + 大师腰带。
5. 解锁顺序用 `UNLOCK_ORDER` 做展示排序，同时充当 `cooldowns` 的键集合。

**耦合点**：`available_plants()` 是"查询"，但会**修改 `self.artifacts`**（1851、1856）。于是"绘制选卡界面"这一纯表现动作，会静默地给玩家发神器。

## G12 无尽模式

1. 判定：`LEVELS[level_index].get("endless")`，只在 index 15。

## G13 界面状态机与快捷操作

**状态**：`mode ∈ {menu, seed_select, playing}` × `overlay ∈ {"", paused, won, lost, warp}`

**快捷操作**：`Tab/N` 下一关、`P` 上一关、`L` 传送门、`Esc` 分层退出、`Space/P`（暂停，与"上一关"冲突）、`1–9` 选卡、`R` 推荐、`C` 清空（选卡界面）/ 一键吸阳光（战斗中）、`F11/F/Alt+Enter` 全屏、右键取消选中。

> **键位表没有单一数据源，且已经冲突**：`P` 键在 1960 被定义为"上一关"并 `return`，导致 2004–2015 的"暂停/继续"分支**永远不可达**；`Space` 在 README 里写作"暂停"，实际在 2012 是 1x/2x 倍速。只有 `Esc` 能暂停。`Tab/N/P/L` 这套跳关键位与选卡界面、战斗界面的键位在同一个方法里串联，靠 `return` 顺序决定优先级。

## G14 全屏/缩放/视口

1. `canvas` 固定 1200×760，所有绘制都写 canvas。
2. `render_present` 在窗口模式直接 blit；全屏模式 `smoothscale` + 居中黑边。
3. 鼠标坐标 `get_logical_mouse_pos` 反向变换。
4. `pygame.mouse.get_pos()` 在 HUD/选卡/覆盖层里被**直接调用 5 次**（3939、4049、4094、3651、3706 区域），**绕过了** `get_logical_mouse_pos` → 全屏下 hover 判定错位。

## G15 音频

`AudioBank` 用程序合成 13 个音效（`_tone` 用数组生成 PCM），音乐按 `music_<track>.mp3` 播放。

**耦合点**：53 处 `self.audio.play(...)` 散落在玩法代码里（`_update_plants` 14 处、`_update_zombies` 14 处），音效时长/冷却参数（`cooldown=0.1/0.3`）混在规则代码中。**没有任何一处是"领域事件"**——规则知道音效名。

## 汇总：玩法规则的"归属地"统计

| 归属地 | 承担规则条目 | 说明 |
|---|---|---|
| A 配置表 | 8 条（数值） | 只覆盖 hp/cost/cooldown/speed/damage |
| B 工具函数 | G1 全部、G15 全部 | 几何与音频是唯一被抽出模块级的领域逻辑 |
| C 绘制函数 | 视觉表现 | 但 `draw_plant` 读 `plant.squash_state/swallow_timer` |
| D 实体类 | G6 运动、G8 推车、G5 部分 | 实体主动调 `game.*` |
| **E Game** | **其余全部** | 2790 行，61 方法 |

**结论**：玩法规则几乎 100% 落在 `Game`，而 `Game` 同时承担字段存储、规则执行、输入解析、布局计算、绘制编排、平台适配、磁盘 IO。规则本身（数值+判定）在配置表里只有 4 个字段的表达力。
