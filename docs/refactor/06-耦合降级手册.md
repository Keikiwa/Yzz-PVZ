> 本文是 `03` 的施工版：每一节给出**现状代码**、**改法**、**改完得到的耦合等级**、**可验证的收益**。

## 0. 降级手法速查

| 手法 | 用于 | 把 X 降为 Y |
|---|---|---|
| **端口/协议注入** | 实体反向调用宿主 | 内容/标记 → 数据 |
| **值对象归集** | 多个裸字段表达同一概念 | 公共 → 数据 |
| **纯函数抽出** | 布局、算法被状态绑死 | 公共/标记 → 数据 |
| **单一权威** | 同一规则多份实现 | 内容 → 数据 |
| **事件下沉** | 规则里出现表现副作用 | 内容 → 非直接 |
| **DTO 快照** | 表现层读模型内部 | 标记/内容 → 数据 |
| **枚举 + 启动自检** | 字符串跨模块约定 | 外部 → 数据（失败提前到启动期） |
| **路由表** | 巨型 `if/elif` 分支 | 公共 → 数据 |

## 1【P1】绘制写命中框 → 布局纯函数

### 现状（公共耦合 + 内容耦合，且有时序依赖）

```python
# 绘制路径（每帧）
_draw_menu(3534)          self.level_buttons = []
_draw_seed_select(3649)   self.slot_rects = []
_draw_seed_select(3705)   self.catalog_rects = {}
_draw_hud(3928)           self.seed_rects = {}
_draw_overlays(4093)      self.warp_buttons = []

# 输入路径（随时）
_handle_click(2066)       for rect, index in self.level_buttons: ...
_handle_click(2087)       for i, rect in enumerate(self.slot_rects): ...
_handle_click(2093)       for name, rect in self.catalog_rects.items(): ...
_handle_click(2173)       for name, rect in self.seed_rects.items(): ...
```

已证实的三个故障：
1. **未 draw 即无法点击**：`headless=True` 或 `start_level` 后首帧前，`seed_rects` 为空 → 点击全部失效。`tools/test_pool_planting_and_cards.py` 因此必须"先 `game.draw()` 再 `_handle_click`"。
2. **全屏下 hover 与 click 不一致**：`_draw_hud` 用 `pygame.mouse.get_pos()`(3939) 判 hover，`handle_events` 用 `get_logical_mouse_pos()`(1931) 判 click。
3. **绘制路径有领域副作用**：`_draw_seed_select`(3697) → `available_plants()`(1831) → `self.artifacts.add(...)`(1851) → **每帧都可能给玩家发神器**。

### 改法

```python
# app/hud_layout.py —— 纯函数，零 pygame 依赖（用 4 元组代替 Rect）
@dataclass(frozen=True)
class HitRegion:
    id: HitId
    x: int; y: int; w: int; h: int
    def contains(self, p: tuple[int,int]) -> bool:
        return self.x <= p[0] < self.x+self.w and self.y <= p[1] < self.y+self.h

@dataclass(frozen=True)
class LayoutSpec:
    regions: tuple[HitRegion, ...]
    draw_cmds: tuple[DrawCmd, ...]

def build_battle_hud(view: "BattleView", mouse: tuple[int,int]) -> LayoutSpec:
    regions, cmds = [], []
    for i, seed in enumerate(view.deck):
        x = HUD_DECK_X + i * (CARD_W + GAP)
        regions.append(HitRegion(HitId.seed(seed.id), x, 12, CARD_W, 76))
        cmds.append(DrawCmd(kind="seed_card", seed=seed, rect=(x,12,CARD_W,76),
                            hover=..., affordable=..., cooldown_ratio=...))
    return LayoutSpec(tuple(regions), tuple(cmds))
```

```python
# infra/pygame_input.py —— 只认识 HitRegion
def hit_test(spec: LayoutSpec, canvas_pos) -> HitId | None:
    return next((r.id for r in spec.regions if r.contains(canvas_pos)), None)

# app/game_loop.py —— 每帧只算一次
spec = build_battle_hud(view_of(world, session), viewport.to_canvas(raw_mouse))
intent = pygame_input.poll(spec)          # 返回 Intent，不是坐标
controller.dispatch(intent, session, world)
renderer.present(spec.draw_cmds)
```

### 收益
- 布局可**离线单测**（`build_battle_hud(view, (500,20)).regions[...].contains((520,30)) == True`）。
- 点击不再依赖"这一帧是否绘制过"。
- hover 与 click 共享同一个 `mouse` 参数 → 全屏行为一致。
- 绘制路径**无法**再修改领域状态（纯函数没有 `self`）。

**等级变化：公共耦合 → 数据耦合。**

### 改法

```python
# domain/rules/damage.py
def apply_damage(zombie: Zombie, amount: float, *,
                 freeze: bool = False,
                 source: DamageSource,
                 sink: EventSink) -> None:
    if not zombie.alive:
        return
    outcome = zombie.take_damage(amount, freeze=freeze)   # 实体自身处理护盾/HP
    if outcome.absorbed:
        sink.emit(ShieldHit(zombie.id, zombie.x, zombie.y))
    if outcome.shield_broken:
        sink.emit(ShieldBroken(zombie.id))
    if outcome.died:
        sink.emit(ZombieKilled(zombie.id, zombie.x, zombie.y, source))
    else:
        sink.emit(ZombieHit(zombie.id, freeze))
```

```python
# domain/model/zombie.py
def take_damage(self, amount: float, *, freeze: bool = False) -> DamageOutcome:
    if self.shield_hp and self.shield_hp > 0:          # 读报：护盾优先
        self.shield_hp -= amount
        if self.shield_hp <= 0:
            self.shield_hp = 0
            self.enrage()
            return DamageOutcome(shield_broken=True)
        return DamageOutcome(absorbed=True)
    self.hp -= amount
    if freeze:
        self.apply_status(Status.slow, 5.0)
    if self.hp <= 0:
        self.kill(DeathCause.damage)
        return DamageOutcome(died=True)
    return DamageOutcome()
```

调用点全部改为 `apply_damage(z, 22.0, source=DamageSource.spikeweed, sink=events)`：
`2707`、`2733`、`2828`、`2998`、`3344`、`3355`、`3159`、`3028`、`3039`、`3082/3086/3091/3100/3106/3117`。

### 收益
- 一条规则一个实现，行为一致（读报在地刺/核弹下也正确）。
- 伤害来源可统计（"本局地刺造成 1200 伤害"变得可行）。
- 新增伤害来源（新植物/新弹种）不需要再抄一遍。

**等级变化：内容耦合 → 数据耦合（多实现 → 单权威）。**

## 3【P2】`elif plant.ptype ==` 链 → 行为配方表

### 现状

`_update_plants` 349 行，27 个 `elif plant.ptype == "..."` 分支，分支间共享隐式上下文（`plant.action_timer`、`self.projectiles`、`self.suns`、`self.zombies`、`self.audio`、`self.burst`…）。新增一种植物要改 8 处（`03` 已列）。

### 改法：把"能力"数据化，把"执行"变成策略表

```python
# domain/spec/plants.py
@dataclass(frozen=True)
class BehaviorSpec:
    kind: BehaviorKind                    # producer|shooter|pult|melee|exploder|aura|homing|laser
    interval: float | None = None         # 触发周期

    rows_spread: int = 0                  # threepeater=1
    area_radius: float = 0.0

    produce: ProduceSpec | None = None    # 产阳光

PLANTS = {
  "sunflower": PlantSpec(..., behavior=BehaviorSpec(
        kind=BehaviorKind.producer, interval=7.0, first_interval=4.1,
        produce=ProduceSpec(value=25, count=1))),
  "threepeater": PlantSpec(..., behavior=BehaviorSpec(
        kind=BehaviorKind.shooter, interval=1.45, damage=20,
        bullet=BulletSpec.pea(), rows_spread=1)),
  "cobcannon": PlantSpec(..., behavior=BehaviorSpec(
        kind=BehaviorKind.pult, interval=15.0, damage=1800,
        bullet=BulletSpec.cob(), area_radius=150, auto_target="max_hp")),
  ...
}
```

```python
# domain/rules/plant_behaviors.py —— 每种 kind 一个函数，注册表分派
BehaviorFn = Callable[[Plant, World, float, EventSink], None]
REGISTRY: dict[BehaviorKind, BehaviorFn] = {
    BehaviorKind.producer: _run_producer,
    BehaviorKind.shooter:  _run_shooter,
    BehaviorKind.pult:     _run_pult,
    BehaviorKind.melee:    _run_melee,
    BehaviorKind.exploder: _run_exploder,
    BehaviorKind.aura:     _run_aura,
    BehaviorKind.homing:   _run_homing,
    BehaviorKind.laser:    _run_laser,
}

def step_plants(world: World, dt: float, sink: EventSink, lanes: LaneQuery) -> None:
    for plant in world.plants:
        spec = PLANTS[plant.spec_id].behavior
        plant.tick(dt)                       # 计时统一由实体负责（修 2396/2476 双递增）
        REGISTRY[spec.kind](plant, world, dt, sink)
```

需要"一次性特殊逻辑"的少数植物（`magicshroom` 的 25% 魅惑、`agave` 的残血斩杀、`squash` 的三段状态机）保留为 `BehaviorKind.special` + 一个 `special_handler` 字段指向函数名，但**依然只在一个文件里**，不再是 349 行的 `elif` 链。

### 收益
- 新增植物：改 `PLANTS`（1 处）+ 补资源（1 处），**不再改战斗代码**。
- 每种行为的参数可被工具读取（例如自动生成"植物强度表"）。
- `_update_plants` 从 349 行缩到约 60 行（`step_plants` + 8 个 15~30 行行为函数）。

**等级变化：不改变耦合等级，但把"配置表达力"从 4 字段提到 12 字段，消除了"行为只能写死在分支里"的根因。**

## 6【P3】5 个裸字段 → `FieldLayout`

### 现状（公共耦合，已经出过 bug）

`is_pool / pool_rows / rows / cell_h / grid_bottom` 在 `start_level`(1652–1656) 一起赋值，之后 20+ 处读。
泳池的行几何有**三份互不引用的常量 + 一处手写阈值**：

```
455 cell_center    POOL_ROW_CENTERS = [155,265,406,498,615,705]; x = 140+(col+.5)*80
469 lane_ground    POOL_LANE_GROUNDS = [190,300,435,528,645,735]
1911 get_cell_rect POOL_ROW_RANGES = [(95,210),(210,335),...]; gx = 140+col*80
2255 _cell_at      手写 90/210/335/452/560/660/755 阈值
```

**已发生的 bug（实测）**：`lane_ground` 38 处调用里只有 2 处传了 `is_pool`（`Zombie.y`/`Zombie.rect`）。于是 `draw_zombie`(1060)、`kill_zombie`(3327)、`_explode_radius`(3342)、`_burn_lane`(3352)、`Mower.update`(1543) 全部退化到陆地公式，且其中多数连 `cell_h` 都用默认 116（泳池是 96）。泳池关因此并存三套地面高度：

| 行 | ① 逻辑（`POOL_LANE_GROUNDS`） | ② 渲染（`cell_h=96` 陆地公式） | ③ 判定（默认 `cell_h=116`） |
|---:|---:|---:|---:|
| 0 | 190 | 212 | 227 |
| 1 | 300 | 308 | 343 |
| 2 | 435 | 404 | 459 |
| 3 | 528 | 500 | 575 |
| 4 | 645 | 596 | 691 |
| 5 | 735 | 692 | 807 |

- 僵尸视觉位置与逻辑位置偏 8–49px
- 投手落点/爆炸特效与僵尸视觉偏 8–49px
- 爆炸命中判定与真实位置偏 24–72px（土豆雷在第 4 行有 35px 宽的水平区间判定错误）
- 死亡粒子与整行火焰飘在僵尸上方

> 根因不是"忘了传参"，而是 `is_pool` 与 `cell_h` 是**可选参数**——调用方有权不传，编译器不报警，测试也不会失败。

### 改法

```python
# domain/spec/field_layout.py
@dataclass(frozen=True)
class FieldLayout:
    cols: int; rows: int; cell_w: int; cell_h: int
    origin: tuple[int,int]
    row_centers: tuple[int,...]      # 长度 == rows
    row_grounds: tuple[int,...]
    row_bounds: tuple[tuple[int,int],...]
    pool_rows: frozenset[int]

    def center(self, col,row):   return (self.origin[0]+int((col+.5)*self.cell_w), self.row_centers[row])
    def ground_y(self, row):     return self.row_grounds[row]
    def cell_rect(self, col,row): 
        t,b = self.row_bounds[row]; return (self.origin[0]+col*self.cell_w, t, self.cell_w, b-t)
    def is_water(self, row):     return row in self.pool_rows
    def cell_at(self, x,y):      # 唯一反解实现
        ...

LAND_LAYOUT = FieldLayout(cols=9, rows=5, cell_w=111, cell_h=116, ...)
POOL_LAYOUT = FieldLayout(cols=9, rows=6, cell_w=80,  cell_h=96,  pool_rows=frozenset({2,3}), ...)
```

所有读取点改为 `world.layout.ground_y(row)` / `world.layout.cell_rect(col,row)`。**`lant_ground(row, is_pool)` 这类"可选参数忘了传"的隐患消失**——布局是对象，不传就没有。

**等级变化：公共耦合 → 数据耦合（不可变值对象）。**
