## 5. 依赖矩阵（谁调用谁）

```
                       ┌──────────────────────────────────────────┐
                       │  main() / parse_args                     │
                       └───────────────┬──────────────────────────┘
                                       │ 创建
                       ┌───────────────▼──────────────────────────┐
                       │  Game (61 方法 / 138 属性)                │
                       └─┬──────┬──────┬──────┬──────┬────────────┘
        ┌────────────────┘      │      │      │      └────────────────┐
        ▼                       ▼      ▼      ▼                       ▼
  pygame.* (display,       PLANTS    LEVELS  AudioBank            pvz_graphics.*
  mouse, event, font,      ZOMBIES   LEVEL_  FontBook             (34 个函数/全局缓存)
  mixer, transform)        UNLOCK_   REWARDS
                           PLANT_TIPS
        ▲                       ▲
        │                       │ 读写
  Projectile.update(game)  Mower.update(game)
  Zombie.y -> lane_ground  Plant.__post_init__ -> cell_center
```

关键观察：

1. **实体反向依赖全局函数**：`Plant.__post_init__` 调 `cell_center`(1375)，`Zombie.y` 调 `lane_ground`(1426)，`kill_zombie` 调 `lane_ground`(3327)。实体无法脱离该模块的模块级函数独立存在。
2. **实体反向依赖 `Game`**：`Projectile.update(dt, game)` 读 `game.zombies`(1485)，`Mower.update(dt, game)` 读 `game.sun / game.artifacts / game.audio / game.zombies` 并调 `game.kill_zombie / game.float_text / game.burst`(1537–1551)。
3. **`pvz_graphics` 反向被喂模型对象**：`draw_plant(..., plant=plant)` 会把 `Plant` 原样交给图形层；图形层读 `plant.squash_state`(:941)、`plant.swallow_timer`(:960)。`render_zombie_sprite(zombie)` 读 `eating/enraged/hypnotized/...`。
4. **绘制路径写状态**：`_draw_menu`(3531) 与 `_draw_seed_select`(3697) 每帧调 `load_save()` / `available_plants()` → **每帧磁盘 IO**；`_draw_hud`(3928) 写 `seed_rects`、`_draw_seed_select`(3649/3705) 写 `slot_rects`/`catalog_rects`、`_draw_menu`(3534) 写 `level_buttons`、`_draw_overlays`(4093) 写 `warp_buttons`。
5. **`available_plants()` 是"查询"却会写 `self.artifacts`**(1851/1856)，并每次重读磁盘(1834)。

## 6. 板块间的隐式契约（没有类型、没有断言）

| 契约 | 载体 | 一旦破坏 |
|---|---|---|
| `ZOMBIES` 字典的**插入顺序** == `LEVELS[i]["mix"]` 9 元组的**位置语义** | `types = list(ZOMBIES)`(1757) 与 `zip(types, mix)`(1782) | 调整字典顺序 → 每关的僵尸配比整体错位，且无报错 |
| `mix` 长度恒为 9 | 全部 `LEVELS` 条目 | 新增第 10 种可刷僵尸 → `zip` 静默截断 |
| 关卡 `theme` 字符串 == `assets/maps/<theme>` 文件名 == `music_<track>.mp3` | `_background`、`play_music` | 改名即静音/无背景 |
| 植物 `ptype` == `assets/plants/<key>/` 目录名 == `assets/cards/card_<key>.png` | `pvz_graphics.init_graphics` | 新增植物需同步 3 处命名 |
| `bullet_type` 字符串 == 图形层分支条件 | `get_bullet_surface`、`_draw_entities` | 新弹种无声不显形 |
| 存档 JSON 键名 `completed/artifacts/endless_best/highest_level` | `load_save`/`record_win`/`available_plants` | `highest_level` 全项目**从未被写入**，只被读(1661) |
| 池泳行号恒为 `[2,3]`、池泳列几何恒为 `x∈[140,860)` | 6 处硬编码（见 03 §2.3） | 改动矩阵需改 6 个地方 |

`LEVELS` 实测：16 条，`pool=True` 的为 index 10–15，`endless` 仅 index 15；`mix` 只覆盖 `ZOMBIES` 前 9 个键，`dolphin/gargantuar/imp/balloon/jackbox/digger` **永远不会由 `_build_waves` 刷出**（只可能在 `setup_preview` 或手工构造里出现）。

### 泳池关的三套地面高度（实测）

同一个"第 row 行的地面线"，代码里存在三条计算路径，各自被不同子系统使用：

| 路径 | 代码 | 使用者 |
|---|---|---|
| ① 逻辑 | `lane_ground(row, cell_h=96, is_pool=True)` → `POOL_LANE_GROUNDS` | `Zombie.y`(1426)、`Zombie.rect`(1429) |
| ② 渲染 | `lane_ground(row, cell_h=96)` → 陆地公式 `GRID_Y+(row+1)*96-8` | `draw_zombie`(1060) |
| ③ 判定/特效 | `lane_ground(row)` → 陆地公式，**且 cell_h 用默认 116** | `kill_zombie`(3327)、`_explode_radius`(3342)、`_burn_lane`(3352)、`Mower.update`(1543-1544) |

| 行 | ① 逻辑 | ② 渲染 | ③ 判定 | ①−② | ①−③ |
|---:|---:|---:|---:|---:|---:|
| 0 | 190 | 212 | 227 | +22 | +37 |
| 1 | 300 | 308 | 343 | +8 | +43 |
| 2（水） | 435 | 404 | 459 | −31 | +24 |
| 3（水） | 528 | 500 | 575 | −28 | +47 |
| 4 | 645 | 596 | 691 | −49 | +46 |
| 5 | 735 | 692 | 807 | −43 | +72 |

后果：僵尸**画在 ② 上、逻辑上是 ①**（视觉与逻辑偏 8–49px）；爆炸/死亡粒子用 ③（与逻辑偏 24–72px）；投手落点用 ①（与视觉偏 8–49px）。实测土豆雷（r=82）在第 4 行有 **35px 宽**的水平区间"命中判定与画面不符"，樱桃炸弹（r=165）为 14px。

### 三张泳池行常量表的自洽性

| 行 | `ROW_CENTERS` | `ROW_RANGES` 中点 | 中心误差 | `LANE_GROUNDS` | 地面−中心 |
|---:|---:|---:|---:|---:|---:|
| 0 | 155 | 152 | −3 | 190 | +38 |
| 1 | 265 | 272 | +7 | 300 | +28 |
| 2 | 406 | 393 | −13 | 435 | +42 |
| 3 | 498 | 506 | +8 | 528 | +22 |

`ROW_RANGES` 的中点是"格子中心"，与 `ROW_CENTERS` 基本吻合（≤13px）；`LANE_GROUNDS` 是"格子底部的地面线"，比中心低 22–42px，符合预期。**三张表本身是自洽的**——问题在于上面那 5 个调用点传参不完整，退化成了陆地公式。
