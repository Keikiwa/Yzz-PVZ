## 一句话结论

**这个项目的核心问题是"边界错位"而不是"耦合太多"**：玩法规则几乎 100% 塞进一个 2790 行的 `Game` 类，而 `Game` 同时承担状态存储、规则执行、输入解析、布局计算、绘制编排、平台适配与磁盘 IO；真正必须存在的耦合（规则↔实体、规则↔几何、规则↔数值）只有 4 类，其余大量"重耦合"是被实现方式造出来的，可以逐条降级。

## 四个问题的答案（摘要）

### Q1「主要玩法逻辑散落在哪里」

三大落点，按承担比例：

1. **`Game` 类占 63%**（2790/4436 行）。其中三个 update 方法 `_update_plants`/`_update_zombies`/`_update_projectiles` 合计 **729 行**，承载 34 种植物、15 种僵尸、14 种弹道的全部行为；`_handle_click`(205 行) 承载 8 种 UI 上下文的点击；7 个 `_draw_*` 合计 822 行。
2. **配置表只覆盖 4 个数值字段**（`hp/cost/cooldown` + 僵尸的 `speed/damage`）。行为无法数据化，只能写进 `if plant.ptype == "xxx"` 分支。
3. **几何规则有 4 个实现**：`cell_center` / `lane_ground` / `get_cell_rect` / `_cell_at`；泳池行几何另有三张常量表（`POOL_ROW_CENTERS` / `POOL_LANE_GROUNDS` / `POOL_ROW_RANGES`）虽彼此自洽但互不引用，靠人工同步。

### Q2「都实现了什么玩法」

15 个玩法族、约 90 条可感知规则。规模最大的三块：
- **植物 34 种**，全部靠 `_update_plants` 的 27 个 `elif` 分支实现（经济/直射/穿透/抛投/追踪/近战/爆炸/控场）。
- **僵尸 15 种**，其中 6 种有特殊 AI（撑杆、海豚、巨人抛小鬼、小丑自爆、矿工遁地、潜水）。
- **弹道 14 种**，运动维度（直线/抛物线/追踪/多向/穿透）× 弹种维度（pea/fire/fume/melon/butter/cob…）。
另有：阳光经济、种植与卡槽（含睡莲承载与植物升级）、波次节奏（含 HP 驱动的波间推进）、割草机、胜负结算、解锁与神器、无尽模式、菜单/选卡/传送门界面状态机、全屏缩放、音频。

详见 `02`。

### Q3「哪些耦合是必须的」

只有 5 类无法也不该消灭，其余都应降级：

| # | 必须的耦合 | 本质 | 应被降级为 |
|---|---|---|---|
| N1 | 规则 ↔ 实体状态 | 模拟器驱动实体 | 数据耦合（经端口接口） |
| N2 | 规则 ↔ 网格几何 | 碰撞必须知道格子尺寸 | 数据耦合（传 `FieldLayout` 值对象） |
| N3 | 规则 ↔ 配置数值 | 天然的数据耦合 | 保持，但扩充表表达力 |
| N4 | 领域事件 ↔ 表现 | 产品需求 | 非直接耦合（事件队列） |
| N5 | 点击 ↔ 命中区域 | 交互必需 | 数据耦合（布局纯函数产出） |

**其余都是被实现方式造出来的**：4 套伤害实现、绘制写命中框、`self.sun` 7 处直写、5 个字段描述同一件事、`setattr` 动态挂字段、53 处规则里直调 `audio.play`、6 组跨模块字符串约定。

详见 `03`。

### Q4「如何降级」

按投入产出排序的 11 条路径（`03 §6`），其中前四条能同时修掉真实缺陷：

| 序 | 降级 | 顺带修掉 |
|---|---|---|
| 1 | 绘制写 rect → 布局纯函数 | 未绘制即无法点击、全屏下 hover 错位、**绘制路径每帧给玩家发神器** |
| 2 | 4 套伤害 → 唯一 `apply_damage` | **读报僵尸被地刺/核弹击杀时报纸不碎** |
| 3 | `hp/alive` 直写 → 实体方法 | 漏掉死亡粒子/音效/统计 |
| 4 | `update(dt, game)` → 端口注入 | 弹丸/推车无法单测 |
| 5 | 5 字段 → `FieldLayout` | **38 处 `lane_ground` 里 36 处漏传 `is_pool`，泳池僵尸渲染偏移最多 49px** |
| 6 | `self.sun` → `SunEconomy` | 无法加阳光统计/上限 |
| 7 | `setattr` → 真字段 | 静态检查失效 |
| 8 | `draw_plant(plant=...)` → 渲染快照 | **`submerged` 字段名不一致导致潜水渲染失效** |
| 9 | 53 处 `audio.play` → 事件订阅 | 规则层无法静音测试 |
| 10 | `artifacts` set → 效果注册表 | **`rapid_seeds` 死码、`master_belt` 构造期失效** |
| 11 | 字符串约定 → 枚举 + 启动自检 | **`highest_level` 永假条件、`ZOMBIES` 顺序隐式依赖** |

详见 `06`（每条都有 before/after 代码）。

## 扫描中顺带发现的 17 条真实缺陷

这些**不是"代码风格问题"，而是能观察到的行为错误**。共 17 条（完整清单见 `06 §16`），其中 9 条已用脚本实测复现（A–I），8 条由代码阅读静态确认。

### 已复现（有运行输出）

**A. 伤害绕过读报护盾**

```python
# 地刺打读报僵尸 40 次（0.45s/次）
z = Zombie("newspaper", 0, 400, 280, 280, 14.0, 28.0)
z.has_newspaper = True; z.newspaper_hp = 140.0
# 实际:  hp=-6  has_newspaper=True  enraged=False
# 期望:  hp=280 has_newspaper=False enraged=True   ← 先扣 140 报纸护盾，再暴怒
```
核弹（`_explode_radius`）同样：`hp=-1520, has_newspaper=True, dead=True` —— 报纸僵尸被一击炸死，报纸从未碎裂、从未暴怒。
原因：`_damage_zombie` 处理护盾，但 `spikeweed`(2707)、`iceshroom`(2733)、`_explode_radius`(3344)、`_burn_lane`(3355)、`jackbox`(2828) 五处直接改 `hp`。

**B. 泳池关：同一行有三套"地面高度"**

`lane_ground` 有 38 处调用，其中 **36 处没传 `is_pool`**（只有 `Zombie.y` / `Zombie.rect` 传了）。而 `draw_zombie`、`kill_zombie`、`_explode_radius`、`_burn_lane`、`Mower.update` 连 `cell_h` 也用了默认值 116（泳池实际是 96），于是三套数值并存：

| 行 | ① 逻辑地面 `POOL_LANE_GROUNDS`（`Zombie.y` 用） | ② 渲染地面 `lane_ground(row, cell_h=96)`（`draw_zombie` 用） | ③ 爆炸/死亡判定 `lane_ground(row)` 默认 cell_h=116 | ①→② 视觉偏差 | ①→③ 判定偏差 |
|---:|---:|---:|---:|---:|---:|
| 0 | 190 | 212 | 227 | +22 | +37 |
| 1 | 300 | 308 | 343 | +8 | +43 |
| 2（水） | 435 | 404 | 459 | −31 | +24 |
| 3（水） | 528 | 500 | 575 | −28 | +47 |
| 4 | 645 | 596 | 691 | −49 | +46 |
| 5 | 735 | 692 | 807 | −43 | +72 |

由此产生的可感知错误：

1. **僵尸画错位置**：视觉中心 = ②−50，逻辑中心 = ①−50，两者相差 8–49px（第 0 行低 22px、第 4 行高 49px）。
2. **投手落点视觉偏移**：卷心菜/玉米/西瓜/冰西瓜/加农炮用 `target.y`（= ①−50）算落点与爆炸特效，但僵尸画在 ② 上 → 落点与僵尸视觉位置差 8–49px。命中判定本身只比较"行 + x 距离"（3070 行），所以**不会真的打空**，但视觉上西瓜/爆炸明显偏离僵尸，泳池关看起来"擦边"。
3. **爆炸判定错位**：`_explode_radius` 用 ③−50，与真实位置偏 24–72px。实测土豆雷（半径 82）在第 4 行有 35px 宽的水平区间命中判定与真实几何不符，樱桃炸弹（半径 165）有 14px——即边缘处的"打中/没打中"与画面不符。
4. **死亡粒子与整行火焰**落在 ③ 的高度，视觉上飘在僵尸上方。

**C. 幽灵预览画"可升级"，点击却拒绝**

```python
# 场上已有 repeater，选中 gatlingpea，点击该格
# 实际:  植物数 1 -> 1, sun 未扣减（"这里已有植物"）
# 预览:  can_plant = True（3886–3905 显式实现了升级分支）
```
`_handle_click` 的种植段（2211–2240）**完全没有升级逻辑**，只有预览有 → 机枪射手/双子向日葵**永远无法落地**。

**D. 潜水僵尸"啃食时浮出"从未生效**

```python
z = Zombie("snorkel", ...); z.eating = 1.0; z.is_submerged = False   # 逻辑: 浮出
getattr(z, "submerged", True)   # 渲染层读的是这个名字 -> True   # 永远潜水
```
模型字段 `is_submerged`(1414)，图形层读 `submerged`(460/522) → `getattr(...,True)` 恒真。

**E. 大师腰带首次进入第 16 关不生效**

```
start_level(15) 第一次: slot_capacity = 9   artifacts 含 master_belt
start_level(15) 第二次: slot_capacity = 10
```
原因：`start_level` 在 1659 行算 `slot_capacity`，而 `master_belt` 要到 1672 行调 `available_plants()`(1856) 才被加入。

**F. 无尽模式第 6 行永不刷僵尸**

```
无尽 12 轮后行分布: {0:5, 1:7, 2:10, 3:6, 4:7}   self.rows = 6
第 6 行(索引 5) 出现次数: 0
```
`_spawn_endless_wave` 用模块常量 `ROWS`(5) 而非 `self.rows`(6)。

**G. 绘制路径每帧触碰磁盘**

```
seed_select 模式 draw 5 帧 -> SAVE_FILE.exists() 调用 7 次
```
`_draw_menu`(3531) 与 `_draw_seed_select`(3697→`available_plants`→1834) 都在绘制里读存档。

**H. 跳关赠送的神器：会话内不回滚、也不写盘**

```
初始 artifacts: []
start_level(9)  后: ['golden_shovel', 'sun_vault']
start_level(0)  后: ['golden_shovel', 'sun_vault']   ← 回第 1 关仍保留
存档文件实际内容: (无)
```
`available_plants()` 名为查询却 `self.artifacts.add(...)`(1851/1856)；副作用发生在查询里，所以"看一眼"就有永久效果，且不落盘。

**I. 未 `draw()` 过则点击全部失效**

```
draw 之前 seed_rects = {}
点击第一张卡牌(160,40) 后 selected_plant = None   (期望 'sunflower')
```
`seed_rects`/`slot_rects`/`catalog_rects`/`level_buttons`/`warp_buttons` 全部只在绘制时填充，`_handle_click` 只读不建 → headless 或首帧前点击全部无效（`tools/test_pool_planting_and_cards.py` 因此被迫"先 draw 再 click"）。

## 一句话给决策者

> 这不是"要不要重构"的问题——`tools/` 里 36 个补丁脚本已经证明，在这个结构上再加功能，代价是"每加一个功能就要写一个一次性的字符串替换器"。重构的收益不只是整洁，而是**把 17 条已发生的静默缺陷连同它们的滋生土壤一起消除**。
